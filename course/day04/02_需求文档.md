# ZL-NA-REQ-004：待办事项管理器 CLI（扩展版）

**版本**：v0.1.0  
**作者**：林薇  
**状态**：已批准

## 1. 需求概述

实现命令行待办管理器，使用 **list** 存储任务，为 Sprint 任务跟踪和 Day 5 JSON 持久化打基础。

## 2. 用户故事

```
作为 NexusAgent 项目组成员，
我希望 在命令行中管理个人 Sprint 待办，
以便 跟踪任务进度、按优先级排序、快速查看未完成项。
```

## 3. 数据模型（每条待办为 list）

```python
# [id, title, description, priority, done]
# id: int 自增
# title: str  非空
# description: str  可空
# priority: int 1=高 2=中 3=低
# done: bool
[1, "完成文本清洗", "批量处理 sample_docs", 1, False]
```

> Day 8 会重构为 Todo 类；Day 5 会改为 dict + JSON。

## 4. 菜单规格

```
====== NexusAgent 待办管理器 ======
1. 添加待办
2. 查看全部
3. 标记完成
4. 删除待办
5. 编辑待办
6. 按优先级排序显示
7. 统计（总数/已完成/未完成）
8. 关键词搜索
0. 退出
```

## 5. 功能需求详述

### 5.1 添加（FR-401）

- 输入标题（必填）、描述（可选）、优先级 1/2/3
- 自动分配递增 id
- 新任务 done=False
- 标题为空时拒绝并提示

### 5.2 查看（FR-402）

- 显示格式：`[ ] #1 [高] 标题 — 进行中`
- 已完成：`[x]`
- 无任务时提示「暂无待办」

### 5.3 标记完成（FR-403）

- 输入 id，将 done 设为 True
- id 不存在时友好提示

### 5.4 删除（FR-404）

- 输入 id，确认后 `pop` 删除
- 支持取消

### 5.5 编辑（FR-405）

- 可单独修改标题或优先级
- 回车跳过表示不修改

### 5.6 排序显示（FR-406）

- 使用 `sorted(todos, key=lambda t: t[3])`
- 不改变原 list 顺序（用 sorted 非 sort）

### 5.7 统计（FR-407）

- 总数 `len(todos)`
- 已完成 `len([t for t in todos if t[4]])`
- 未完成 = 总数 - 已完成

### 5.8 搜索（FR-408）

- 关键词不区分大小写
- 匹配 title 子串
