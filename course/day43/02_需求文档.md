# ZL-NA-REQ-043 产品需求文档（PRD）

**需求名称**：Supervisor 多 Agent 委派
**优先级**：P0
**平台版本**：v0.43.0

---

## 1. 背景

随着工具越来越多，一个 Agent 要同时懂 FAQ、RAG 检索、意图分类，Prompt 越写越长，维护成本飙升。 引入 Supervisor 模式：supervisor_route 节点先判断问题类型，再委派给 faq_worker / rag_worker / intent_worker 三个专职子 Agent 之一执行，最后 synthesize 节点汇总成统一回复。

## 2. 目标

- `agent/supervisor_config.py` — SupervisorConfig — max_delegations
- `agent/sub_agent.py` — 三个专职子 Agent
- `agent/supervisor_graph.py` — supervisor_route → worker → synthesize
- `GET/PUT /api/agent/supervisor-config` 配置读写
- `POST /api/agent/supervisor-preview` 无状态预览

- `POST /api/chat` + `supervisor_mode=true` → `supervisor_trace`

## 3. 功能需求

### FR-001 SupervisorConfig — max_delegations

- 实现位置：`agent/supervisor_config.py`

### FR-002 三个专职子 Agent

- 实现位置：`agent/sub_agent.py`

### FR-003 supervisor_route → worker → synthesize

- 实现位置：`agent/supervisor_graph.py`

### FR-004 持久化与 status

- `store.json` 新增对应 config 字段
- `GET /api/knowledge/status` 含该 config 字段
- `platform_version` 为 `v0.43.0`

### FR-005 Chat 集成

- `api/chat.py` 在 `supervisor_mode=true` 且配置 `enabled` 时走本日管线
- `ChatResponse` 新增 `supervisor_trace` 字段（及 delegated_agents, tools_used）

### FR-006 演示与测试

- `day43/supervisor_demo.py` 打印决策/委派轨迹
- `day43/supervisor_api_demo.py` 演示 REST API
- `tests/day43/` 17 项覆盖单元 + API + chat

## 4. 非功能需求

### NFR-001 可观测性

每次调用都返回结构化 `supervisor_trace`，可用于审计与教学演示。

### NFR-002 兼容性

`supervisor_mode=false`（默认）时行为与之前完全一致，不影响既有回归。

### NFR-003 可测试性

核心类可脱离 FastAPI 直接单测（构造 `ToolExecutor` 后 `invoke`/`run`）。

## 5. 非目标

- 接入真实大模型 function-calling（当前仍为规则/mock 决策）
- 跨 session 的长期记忆持久化
