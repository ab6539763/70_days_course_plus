## 作业 C 参考答案

```python
def classify_reply(reply: str) -> tuple[str, str]:
    text = (reply or "").strip()
    if not text:
        return "system", "空回复"
    if text.startswith("[系统通知]"):
        return "system", "系统通知"
    if text.startswith("[FAQ"):
        return "faq", "FAQ 直答"
    # ... 其余同仓库实现
```

| `[路由: rag_qa] y` | route |
| `你好` | llm |
| `` | system |

## 作业 E 参考答案要点

- FastAPI 托管时无 `?mock=1` → `NexusConfig.useMock` 为 false → `mock.js` 的 `useMock` 为 false → 调用 `sendMessageApi`  
- `?mock=1` 时走本地 Mock，无需后端  
- `apiBase` 用于将来 API 不同域时前缀，如 `https://api.example.com`  
- Day 22 在 `mock.js` 内写死 `useMock: true`；Day 23 外置到 `config.js`，职责分离

## 作业 F 参考答案要点

**优点**：实现简单、无外部依赖、教学演示足够。  
**缺点**：进程重启丢失、多 worker 不共享、无 TTL 踢过期会话。  
**Redis 草图**：`HSET session:{id} orchestrator_state` 或仅存 message history JSON；`EXPIRE` 24h。  
**多 worker**：每 worker 独立 dict，同一用户打到不同 worker 会丢会话——须粘性会话或 Redis。

## 智链科技作业答案深度解析（培训部）

### 关于作业 B kind 判定弹性

讲师批改时须理解：「帮我总结要点」在后端可能走 doc_summary 路由模板，也可能因 Matcher 或 LLM 回落而 kind=llm。验收标准：**reply 非空 + Network 显示 200 + 非 Mock 前缀**。若 kind=llm 但 reply 含完整合规答案，不扣分。若 reply 为「（Mock）助手收到」，判 API 模式失败，须重修环境章节。

### 关于作业 C 与仓库同步

若学员扩展了 classify_reply 但未提 PR，作业仍有效，但须注明「与仓库实现差异」。优秀作业可提议向主仓提 FR 扩展。陈默鼓励「作业驱动小 PR」，但 `[系统通知]` 前缀需产品确认文案。

### 关于作业 D jq 可选

无 jq 环境可用 python -m json.tool 代替。curl 日志须可读，不必漂亮。session_id 实验是 Day 24 前置技能，批改权重高于 jq 格式。
