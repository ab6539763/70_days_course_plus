# ZL-NA-REQ-023 需求文档

**需求编号**：ZL-NA-REQ-023  
**需求名称**：FastAPI Chat REST API  
**优先级**：P0  
**Sprint**：Sprint 3 第九日  
**状态**：已交付

---

## 1. 背景

智链科技 NexusAgent 在 Day 21 交付 `ChatOrchestrator.handle_message`，Day 22 在 `frontend/` 搭建静态聊天页并以 `mock.js` 对齐契约。产品要求：在 `src/api/` 暴露 **REST API**，使浏览器通过 `POST /api/chat` 调用真实编排器，并为 Day 24 网页版 ChatGPT 克隆完整整合提供后端入口。

## 2. 目标用户

- 终端用户（浏览器经 API 获取回复）
- 全栈学员（理解 FastAPI + Pydantic + 依赖注入）
- 产品与运营（Swagger `/docs` 调试、合规 FAQ 验收）
- CI（`test_api_chat.py` 十二项 HTTP 契约守护）

## 3. 功能需求

### FR-001 FastAPI 应用入口 app.py

| 项 | 描述 |
|----|------|
| 文件 | `nexus-agent-platform/src/api/app.py` |
| 工厂 | `create_app(*, enable_cors: bool = True) -> FastAPI` |
| 元数据 | title=`NexusAgent API`，version=`0.23.0` |
| 路由 | `include_router(chat_router)` |
| CORS | 开发环境 `allow_origins=["*"]` |
| 异常 | `ModelValidationError`→400，`ConfigError`→500，`APIError`→502 |
| 静态 | 挂载仓库根 `frontend/` 至 `/`，`html=True` |
| 启动 | `uvicorn api.app:app --reload --port 8000` |

### FR-002 Chat 路由 chat.py

| 项 | 描述 |
|----|------|
| 文件 | `nexus-agent-platform/src/api/chat.py` |
| 前缀 | `APIRouter(prefix="/api", tags=["chat"])` |
| GET | `/api/health` → `HealthResponse`（status, version, mock_llm） |
| POST | `/api/chat` → `ChatResponse` |
| 逻辑 | `SessionManager.get_or_create` → `orchestrator.handle_message` → `classify_reply` |
| 校验 | `message.strip()`，空串由 Pydantic 拦截 |
| 错误 | `ConfigError`/`NexusError`→500，`APIError`→502 |

### FR-003 数据模型 schemas.py

| 项 | 描述 |
|----|------|
| 文件 | `nexus-agent-platform/src/api/schemas.py` |
| ChatRequest | `message: str`（1–2000），`session_id: str \| None`（≤64） |
| ChatResponse | `reply`, `meta`, `kind`, `session_id` |
| HealthResponse | `status`, `version`, `mock_llm` |
| ErrorResponse | `detail`, `code`（文档用） |
| 版本 | Pydantic v2，`Field` 描述中文 |

### FR-004 会话管理 sessions.py

| 项 | 描述 |
|----|------|
| 文件 | `nexus-agent-platform/src/api/sessions.py` |
| 类 | `SessionManager` 内存 dict + `threading.Lock` |
| 方法 | `get_or_create(session_id)` → `(sid, ChatOrchestrator)` |
| 默认 | `session_id` 空或省略 → `"default"` |
| 隔离 | 不同 sid 不同 orchestrator 实例 |
| 单例 | 模块级 `session_manager` 供 `Depends` 注入 |

### FR-005 编排器工厂 factory.py

| 项 | 描述 |
|----|------|
| 文件 | `nexus-agent-platform/src/api/factory.py` |
| 函数 | `create_orchestrator(*, transport, faq_threshold)` |
| 组装 | RAG、FAQ、IntentRouter、ToolRegistry、LLMClient、ChatAssistant、ChatOrchestrator |
| Mock | 默认 `NEXUS_LLM_MOCK=1`，`SAMPLE_MOCK` transport |
| 阈值 | `OrchestratorConfig(faq_direct_threshold=0.65)` |

### FR-006 响应解析 response_parser.py

| 项 | 描述 |
|----|------|
| 文件 | `nexus-agent-platform/src/api/response_parser.py` |
| 函数 | `classify_reply(reply: str) -> tuple[str, str]` |
| FAQ | `[FAQ` 或 `[FAQ 直答` 前缀 → `("faq", "FAQ 直答")` |
| 路由 | 正则 `^\[路由:\s*([^\]]+)\]` → `("route", "路由 · {template}")` |
| 系统 | `请输入` → system；`配置错误`/`API 调用失败` → error |
| 默认 | `("llm", "LLM 回复")` |
| 对齐 | 与 `frontend/app.js parseReply` 语义一致 |

### FR-007 单元测试 test_api_chat.py

| 项 | 描述 |
|----|------|
| 文件 | `tests/day23/test_api_chat.py` |
| 数量 | 12 条 |
| 覆盖 | health、FAQ chat、route/llm、doc_summary、空消息 422、session 保持、classify_reply 三例、session 隔离、frontend 托管、config.js |
| 客户端 | `TestClient(create_app())` |
| 环境 | `NEXUS_LLM_MOCK=1` |

## 8. 需求评审会议纪要（扩展）

### 8.1 评审参与人

智链科技产品、架构、DevOps、合规、培训部代表；林晓作为学员代表列席。

### 8.2 争议项与决议

**争议一**：是否在 Day 23 实现 JWT 鉴权。  
**决议**：否，放入 Sprint 4；内网演示风险可控，避免分散 FastAPI 入门注意力。

**争议二**：`ChatResponse` 是否增加 `score` 字段暴露 FAQ 分数。  
**决议**：否，分数已编码在 `reply` 前缀百分比；避免前端重复展示引发合规争议。

**争议三**：静态 mount 是否导致 API 路径被误配。  
**决议**：是风险，靠测试 `test_frontend_served` 与路由注册顺序保障；文档强调 router 先于 mount。

**争议四**：空 message 返回 422 是否用户友好。  
**决议**：保持 422；前端 `required` 与 trim 已拦截，422 主要防 API 直接调用。
