## 1. API 接口详表

### 1.1 GET /api/health

**用途**：存活探针、版本确认、Mock LLM 状态展示。

```http
GET /api/health HTTP/1.1
Host: 127.0.0.1:8000
```

**200 响应**：

```json
{
  "status": "ok",
  "version": "0.23.0",
  "mock_llm": true
}
```

林晓在演示前必先 curl health，确认 `mock_llm` 与业务话术一致。

### 1.2 POST /api/chat

**请求**：

```http
POST /api/chat HTTP/1.1
Content-Type: application/json

{
  "message": "投资有风险吗",
  "session_id": "sess-demo-001"
}
```

**200 响应**：

```json
{
  "reply": "[FAQ 直答·68%] 投资有风险，入市需谨慎。请阅读风险揭示书。",
  "meta": "FAQ 直答",
  "kind": "faq",
  "session_id": "sess-demo-001"
}
```

**422 响应**（空 message）：

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "message"],
      "msg": "String should have at least 1 character",
      "input": ""
    }
  ]
}
```

**502 响应**（上游 APIError）：

```json
{
  "detail": {
    "detail": "API 调用失败: …",
    "code": "API_ERROR"
  }
}
```

## 8. OpenAPI 示例与 curl 对照全集

### 8.1 FAQ 成功路径

```bash
curl -s -X POST http://127.0.0.1:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"投资有风险吗"}'
```

期望字段：reply 含 FAQ 前缀，kind=faq，session_id=default（若未传 sid）。

### 8.2 路由问句

```bash
curl -s -X POST http://127.0.0.1:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"帮我总结要点"}'
```

kind 可能 route 或 llm，reply 应非空。业务验收看前缀而非仅 kind。

### 8.3 会话保持

两次请求同一 session_id，第二次应能利用同一 orchestrator 历史（若问「我刚才说了什么」类问题——选修实验）。

### 8.4 错误样本库

空 message → 422。超长 message（2001 字）→ 422。非法 JSON → 422。无 body → 422。

### 8.5 Swagger 与 curl 一致性说明

两者应产生相同 status 与等价 body。若不一致，查 Content-Type 或 proxy。培训部要求作业 D 附此说明一段。

### 8.6 智链科技接口版本策略备忘

内测期无 /v1；对外发布时升 /api/v1/chat，旧路径 deprecation 六个月。陈默 2026-Q3 备忘。
