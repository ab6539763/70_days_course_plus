## 1. OpenAI 兼容 API 格式说明

DeepSeek、OpenAI、多数国内大模型厂商采用同一套 REST 契约：

### 1.1 端点

```
POST {base_url}/chat/completions
```

默认：`https://api.deepseek.com/v1/chat/completions`

### 1.2 请求头

```
Content-Type: application/json
Authorization: Bearer <DEEPSEEK_API_KEY>
```

Mock 模式仅需 `Content-Type`。

### 1.3 请求体（示例）

```json
{
  "model": "deepseek-chat",
  "temperature": 0.7,
  "max_tokens": 1024,
  "messages": [
    {"role": "system", "content": "你是企业知识库助手。"},
    {"role": "user", "content": "理财产品年化收益率是多少？"}
  ]
}
```

由 `build_request_body()` 生成，字段来源：

| 字段 | 来源 |
|------|------|
| model, temperature, max_tokens | `ModelConfig.to_api_params()` |
| messages | `[m.to_api_message() for m in messages]` |

### 1.4 成功响应（关键字段）

```json
{
  "id": "chatcmpl-xxx",
  "model": "deepseek-chat",
  "choices": [{
    "index": 0,
    "message": {"role": "assistant", "content": "..."},
    "finish_reason": "stop"
  }],
  "usage": {
    "prompt_tokens": 42,
    "completion_tokens": 18,
    "total_tokens": 60
  }
}
```

`parse_chat_completion()` 提取 `choices[0]` 与 `usage`。

## 2. urllib 选型理由（非功能性需求）

| 考量 | urllib | requests |
|------|--------|----------|
| 依赖 | 标准库 | PyPI 安装 |
| 教学曲线 | 略陡 | 友好 |
| 企业内网 | 无额外审批 | 可能需安全扫描 |
| 测试注入 | transport 抽象即可 | 可用 responses/mock |

**结论**：MVP 与课程阶段使用 `urllib.request`；Day 13 扩展文档对比 `requests`，生产可选用 `httpx`（Day 30+）。

## 3. Transport 注入设计

```python
TransportFunc = Callable[[str, dict[str, str], dict[str, Any]], dict]
```

签名：`(url, headers, payload) -> response_dict`

用途：

1. **default_transport**：真实 `urllib` POST
2. **mock_transport_from_file**：读本地 JSON
3. **单元测试**：lambda 返回伪造响应，无需网络

此模式称为 **依赖注入（Dependency Injection）**，Day 13 装饰器将包装同一 `complete` 入口。

| 项目 | Day 5 `api_response_parser` | Day 12 `llm/response.py` |

| 输入 | 文件 / stdin | HTTP 响应 dict |
