## 14:00 with_timeout 实现

```python
with concurrent.futures.ThreadPoolExecutor(max_workers=1) as pool:
    future = pool.submit(func, *args, **kwargs)
    try:
        return future.result(timeout=seconds)
    except concurrent.futures.TimeoutError as exc:
        raise APIError(f"调用超时（>{seconds}s）") from exc
```

**周航提醒**：

- 超时异常类型统一为 `APIError`，与 HTTP 错误一致，便于 `is_retryable_error` 处理（`status_code=None` → 可重试）  
- `seconds <= 0` 在装饰器工厂层 `raise ValueError`

**问题**（王磊）：为何不用 `signal.alarm`？

> 仅 Unix 主线程；`ThreadPoolExecutor` 跨平台且与 urllib 阻塞模型匹配。

## 14:45 装饰器组合顺序

```python
@retry(...)
@with_timeout(timeout_seconds)
def _call(messages):
    return super().complete(messages)
```

执行顺序：**自下而上装饰，自上而下调用**。

1. 调用进入 `retry` 的 `wrapper`  
2. 每次 attempt 进入 `with_timeout` 的 `wrapper`  
3. 最内层执行 `complete`

**错误顺序演示**（若先 retry 后 timeout 包在外）：

- 超时装饰器在外 → 一次超时杀死所有重试机会（反模式）

`apply_resilience` 工具函数封装正确顺序：

```python
wrapped = with_timeout(policy.timeout_seconds)(func)
wrapped = api_retry(policy)(wrapped)
```

## 15:30 ResilientLLMClient 走读

构造流程：

1. `super().__init__` 继承 Day 12 客户端  
2. `self.policy = policy or RetryPolicy()`  
3. `self._complete_resilient = self._build_resilient_complete()`

## 16:15 asyncio 预习（async_demos.py）

```python
async def fetch_label(name, delay):
    await asyncio.sleep(delay)
    return f"{name} OK"

results = await asyncio.gather(
    fetch_label("doc_reader", 0.1),
    fetch_label("llm_client", 0.1),
    fetch_label("retry", 0.1),
)
```

**对比同步重试**：

| 维度 | 同步 retry + sleep | asyncio |
|------|-------------------|---------|
| 阻塞 | 线程阻塞 | 事件循环协作式 |
| 适用 | urllib MVP | Day 16 SSE 流 |

`asyncio.run(main_async())` 作为程序入口。
