## 1. Python 装饰器协议（PEP 318）

`@decorator` 自 Python 2.4 引入，本质是**函数变换**。类装饰器（`@dataclass`）是后续演进，今日聚焦**函数装饰器**。

推荐阅读：官方文档 [Primer on Python Decorators](https://docs.python.org/3/glossary.html#term-decorator)。

## 2. ParamSpec 与 TypeVar（retry.py 类型）

```python
P = ParamSpec("P")
R = TypeVar("R")

def retry(...) -> Callable[[Callable[P, R]], Callable[P, R]]:
```

**教学点**：装饰器应保留被装饰函数的参数签名，便于 mypy 检查。MVP 可不深讲，指向 TypeVar 章节即可。

## 3. 指数退避与 Jitter 论文参考

AWS 架构博客：[Exponential Backoff And Jitter](https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/)

核心公式对比：

| 策略 | 公式 |
|------|------|
| 纯指数 | `min(cap, base × 2^attempt)` |
| Full jitter | `random(0, min(cap, base × 2^attempt))` |
| Equal jitter | `half + random(0, half)` |

课堂可演示：10 客户端同步重试 vs 加 jitter 的流量分布（口述即可）。

## 5. 重试与幂等性

HTTP POST Chat Completions **非天然幂等**。重试可能导致：

- 重复计费（token 双倍）  
- 重复副作用（若 API 带工具调用）

企业实践：

- 幂等键 `Idempotency-Key` Header（OpenAI 部分支持）  
- 仅对「读类」或「无副作用」重试  
- Day 30 工作流专题展开

## 6. 装饰器与 unittest.mock

```python
with patch.object(client, "complete", wraps=client.complete):
    ...
```

`functools.wraps` 保证 patch 路径与 `__name__` 一致。若自定义装饰器丢失 wraps，mock 可能失效——可在 FAQ 强调。
