## 2. 装饰器相关

### Q: 装饰后函数名变成 `wrapper`

未使用 `@functools.wraps(func)`。检查自定义装饰器是否复制元数据。

### Q: `@retry` 不生效，一次就失败

排查清单：

1. 异常类型是否为 `APIError` 且状态码在白名单？  
2. `ConfigError` / 401 按设计不重试  
3. `max_attempts` 是否为 1？  
4. 是否装饰了错误函数（装饰类方法时注意绑定）

### Q: 带参装饰器写法错误

```python
# 错误
@retry
def f(): ...  # retry 返回 decorator，未调用

# 正确
@retry(max_attempts=3)
def f(): ...
```

---

## 3. 重试与退避

### Q: retry_demos 等太久

课堂脚本用 `base_delay=0.05`。若你改成默认 1s，两次失败约等 3s，属正常。

### Q: 重试次数与预期不符

`max_attempts` **含首次**。`max_attempts=3` 最多 3 次调用、最多 2 次 sleep。

### Q: 503 一直失败

检查 `fail_times` 是否 ≥ `max_attempts`。`resilient_client_demo` 默认 `fail_times=2`、`max_attempts=4`，应成功。

---

## 4. 超时

### Q: `调用超时（>60s）` 后仍重试

超时抛 `APIError` 且无 `status_code` → `is_retryable_error` 返回 True → 进入退避。若不想重试超时，自定义：

```python
def not_timeout_retryable(exc):
    if "调用超时" in str(exc):
        return False
    return is_retryable_error(exc)

@retry(retryable=not_timeout_retryable)
def f(): ...
```

### Q: 超时后 CPU 仍占用

`ThreadPoolExecutor` 无法强杀阻塞中的 urllib。Day 16 异步方案改进。

---

## 5. ResilientLLMClient

### Q: Mock 模式仍报 ConfigError

```bash
export NEXUS_LLM_MOCK=1
```

或构造 `LLMEnvConfig(..., mock=True)`。

### Q: 看不到重试日志

传 `on_retry_log=True`。默认关闭，避免生产刷屏。

### Q: super().complete 在闭包中报错

使用 `super(ResilientLLMClient, self).complete(messages)` 显式形式。

## 6. 测试失败典型栈

| 栈顶消息 | 原因 | 修复 |
|----------|------|------|
| `AssertionError: 2 != 3` | 重试次数假设错误 | 核对 max_attempts 语义 |
| `ValueError: max_attempts 必须 >= 1` | 非法策略 | RetryPolicy 校验 |
| `APIError: rate limited` | demo 未跑完 | 增大 max_attempts |

---

## 7. 调试技巧

```python
# 临时打印 predicate 结果
@retry(max_attempts=3, retryable=lambda e: (print(e, is_retryable_error(e)) or is_retryable_error(e)))
```

使用 `pytest -k test_retry --pdb` 在失败处进入调试器。
