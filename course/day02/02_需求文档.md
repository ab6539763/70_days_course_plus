## 1. 需求概述

### 1.1 背景

NexusAgent RAG 知识库模块在导入企业文档前，必须对原始文本进行标准化清洗。OCR、网页抓取、Word 导出等来源的文本普遍存在多余空白、大小写不一致、敏感信息泄露等问题。

### 1.2 目标

实现命令行工具 `text_cleaner.py`，对单份文本执行标准化清洗，并输出可选的统计报告。

### 1.3 非目标（本期不做）

- 批量目录遍历（Day 11）
- 正则表达式高级模式（Day 11）
- 配置文件热加载（Day 10）
- 数据库持久化清洗记录（Day 24）

---

## 2. 用户故事

```
作为 RAG 模块开发者，
我希望 在命令行中对原始文本执行标准化清洗并查看统计报告，
以便 在文档入库前保证文本质量、避免敏感信息泄露。
```

**验收标准**：

1. 支持从文件读取或直接传入字符串
2. 执行至少 4 项清洗规则（见 3.2）
3. 清洗结果输出到 stdout 或 `--output` 文件
4. `--report` 时输出可读统计报告（f-string 格式化）
5. 敏感词替换不区分大小写

## 3. 功能需求

### 3.1 命令行参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--input` | path | 与 `--text` 二选一 | 输入文件路径（UTF-8） |
| `--text` | string | 与 `--input` 二选一 | 直接传入待清洗文本 |
| `--output` | path | 否 | 输出文件路径，默认 stdout |
| `--lower` | flag | 否 | 是否转为小写，默认 False |
| `--report` | flag | 否 | 是否打印清洗报告 |
| `--help` | flag | 否 | 显示帮助 |

### 3.2 清洗规则（按顺序执行）

| 序号 | 规则 ID | 说明 | 示例 |
|------|---------|------|------|
| 1 | RULE_TRIM | 每行去除首尾空白 | `"  hello  "` → `"hello"` |
| 2 | RULE_COLLAPSE_SPACE | 连续空白字符合并为单个空格 | `"a    b"` → `"a b"` |
| 3 | RULE_COLLAPSE_PUNCT | 连续相同标点合并为 1 个 | `"!!!"` → `"!"` |
| 4 | RULE_SENSITIVE | 敏感词替换为 `***`（不区分大小写） | 见敏感词表 |
| 5 | RULE_LOWER | 可选：全转小写 | `"API"` → `"api"` |
| 6 | RULE_DROP_EMPTY | 删除纯空行 | 减少无意义 chunk |

### 3.3 敏感词表（v0.1）

定义在 `src/day02/constants.py`：

```python
SENSITIVE_WORDS = [
    "内部资料",
    "禁止外传",
    "机密",
]
```

手机号模式 Day 11 用正则处理；Day 2 在敏感词表增加占位项 `"手机号"` 用于演示性替换（样本中含明文手机号时用简单 replace 处理数字串，见实现说明）。

### 3.4 清洗报告格式

```
╔══════════════════════════════════════╗
║     NexusAgent 文本清洗报告           ║
╠══════════════════════════════════════╣
║  输入来源：raw_notice.txt             ║
║  原始字符数：1,284                    ║
║  清洗后字符数：1,102                  ║
║  压缩率：14.2%                        ║
║  敏感词替换次数：3                    ║
║  删除空行数：5                        ║
╚══════════════════════════════════════╝
```
