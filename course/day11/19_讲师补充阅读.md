## 一、pathlib 与 os.path

### 1.1 历史

- Python 3.4 引入 `pathlib`（PEP 428）  
- 3.6+ `Path` 接受纯路径函数；3.8+ 多数场景可替代 `os.path`  

NexusAgent **新代码一律 pathlib**；维护老脚本时可见 `os.path`，不混用同一模块。

### 1.2 对照表

| 任务 | os.path | pathlib |
|------|---------|---------|
| 拼接 | `os.path.join(a, b)` | `Path(a) / b` |
| 父目录 | `os.path.dirname(p)` | `p.parent` |
| 文件名 | `os.path.basename(p)` | `p.name` |
| 后缀 | `os.path.splitext(p)[1]` | `p.suffix` |
| 绝对路径 | `os.path.abspath(p)` | `p.resolve()` |
| 是否存在 | `os.path.exists(p)` | `p.exists()` |
| 是否文件 | `os.path.isfile(p)` | `p.is_file()` |

### 1.3 何时 os.path 仍合理

- 与只接受 `str` 的 C 扩展交互  
- 极简单文件脚本且无需对象语义  

`doc_reader` 已选 pathlib，跟随项目即可。

### 1.4 Path 是 str 吗？

`Path` 继承自 `PurePath`，**不是** `str`，但可与 `str` 互转：

```python
str(Path("a/b"))
Path("/tmp/x")
```

`open(path)` 在 3.6+ 接受 `PathLike`。

## 二、open() 与 Path.read_text / write_text

### 2.1 open 三元组

```python
with open(path, "r", encoding="utf-8") as f:
    content = f.read()
```

优点：流式、可控 buffer、适合 GB 级文件。  
缺点：样板代码多，易忘 `encoding=`（Python 3 默认 UTF-8 平台相关风险）。

### 2.2 read_text 本质

CPython 中大致等价于：

```python
with open(self, mode='r', encoding=encoding) as f:
    return f.read()
```

**一次读入内存**——doc_reader MVP 假设单文件 < 几 MB。

### 2.3 write_text 注意

- 默认**覆盖**已存在文件  
- 不自动 `mkdir` 父目录——须先 `output_dir.mkdir(parents=True, exist_ok=True)`  
- 始终指定 `encoding="utf-8"` 写出清洗结果  

### 2.4 二进制

| 场景 | API |
|------|-----|
| 未知编码 | `read_bytes()` |
| 图片/PDF 原始 | `read_bytes()` / `write_bytes()` |
| 编码回退 | bytes → 循环 decode（见 read_text_file） |

## 三、设计哲学：薄 IO，厚编排

```
open/read_text  → 字节/文本
doc_reader      → 编排 + 异常 + 统计
clean_text      → 领域清洗规则
```

不要在 `doc_reader` 里加新的标点规则；不要在 `clean_text` 里做 glob。

## 四、常见误区

| 误区 | 纠正 |
|------|------|
| Path 会自动猜编码 | 不会，用 read_text_file |
| latin-1 成功=正确 | 可能是乱码兜底 |
| 清洗=加密 | 脱敏不可逆但非加密 |
| tools 可 import day02 | 禁止，用 utils |
