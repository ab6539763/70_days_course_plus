## 一、企业文档编码现状（2026 国内金融 IT）

### 1.1 典型来源与编码

| 来源 | 常见编码 | 备注 |
|------|----------|------|
| Linux 服务日志 | UTF-8 | 标准 |
| Windows Excel 导出 CSV | GBK / UTF-8 BOM | 看「另存为」选项 |
| 老 OA 附件 | gb2312 / GBK | 仍占一定比例 |
| OCR 引擎默认 | UTF-8 | 个别厂商 GBK |
| 邮件正文 | UTF-8 / Base64 | 附件另论 |

智链科技 Day 11 策略：**读入宽容（回退链）、写出统一（UTF-8）**。

### 1.2 为何不统一转码入库前

- 批量转码需额外批处理与失败审计  
- OCR 原稿需法务留存原字节  
- `DocumentRecord.encoding` 记录实际检测编码，供质控抽检

## 二、Python 3 字符串模型实践

### 2.1 黄金法则

1. **内部一律 `str`（Unicode）**  
2. **边界（磁盘/网络）才 bytes**  
3. **encode/decode 显式标注编码名**  

```python
# 边界读入
raw: bytes = path.read_bytes()
text: str = raw.decode("gbk")  # 或通过 read_text_file

# 边界写出
path.write_text(text, encoding="utf-8")
```

### 2.2 常见崩溃点

```python
>>> "智链".encode("ascii")
UnicodeEncodeError
>>> b"\xff\xfe".decode("utf-8")
UnicodeDecodeError
```

`read_text_file` 将后者转化为尝试下一编码。

## 三、DEFAULT_ENCODINGS 运维手册

```python
DEFAULT_ENCODINGS = ("utf-8", "gbk", "gb2312", "latin-1")
```

### 3.1 日志记录建议

```python
record = read_document(path, clean=True)
logger.info(
    "ingest_ok file=%s encoding=%s size=%d",
    record.name, record.encoding, record.size_bytes,
)
```

### 3.2 latin-1 告警规则（Day 28 实现）

若 `encoding == "latin-1"` 且含大量 `\ufffd` 或不可打印字符 → 标记 `quality= suspect`。

### 3.3 自定义 encodings

```python
read_text_file(path, encodings=("utf-8", "utf-16"))
```

仅用于已知 UTF-16 导出的子系统，勿随意缩短列表。

## 四、文件系统与路径编码

### 4.1 Linux

- 路径名是 **bytes**（ext4 等），用户态常用 UTF-8 解释  
- `Path` 接受 Unicode 字符串路径  

### 4.2 Windows

- 历史 API 限制；Python 3.6+ `Path` 处理 Unicode 路径  
- 培训环境 Linux 为主，部署 Windows 时需测长路径  

### 4.3 路径与内容分离

```python
# 文件名可以是中文
p = Path("/tmp/报告.txt")
p.write_bytes("内容".encode("gbk"))  # 内容编码与文件名无关
```

## 五、BOM、换行符与 normal form

### 5.1 UTF-8 BOM

字节序列 `EF BB BF`。解码后可能出现在 `text[0]`。  
处理：`text.removeprefix("\ufeff")` 或 `encoding="utf-8-sig"`（单独策略，未并入 DEFAULT）。

### 5.2 换行符

| 系统 | 换行 |
|------|------|
| Unix | `\n` |
| Windows | `\r\n` |

`splitlines()` 自动处理；写出时 `write_text` 使用 `\n`（Unix 风格），Git 可配置 `autocrlf`。

## 六、权限与安全

### 6.1 PermissionError

```python
# doc_reader 包装为 StorageError
except OSError as exc:
    raise StorageError(...) from exc
```

运维：检查 `chmod`、SELinux、NFS 挂载只读。

### 6.2 路径遍历

用户传入 `../../../etc/passwd` 时：

```python
resolved = user_path.resolve()
if not resolved.is_relative_to(allowed_root):  # 3.9+
    raise StorageError("路径越界")
```

Day 11 MVP 信任 `get_path`；多租户 Day 22+ 加强校验。

## 八、与 Git 的编码

- 仓库默认 UTF-8  
- `.gitattributes` 可设 `* text=auto`  
- 二进制勿当文本提交（PDF 改 .txt 后缀是常见错误）

## 十、企业规范摘要

1. 读：`read_text_file` 或 `read_bytes` + 回退  
2. 写：UTF-8 + `cleaned_` 前缀  
3. 日志：记录 `encoding`、`path`  
4. 异常：`StorageError`，禁止静默  
5. 原稿：只读，不覆盖
