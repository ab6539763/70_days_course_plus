**陈默**：昨天我们把包拆成了 core、models、services。今天 tools 不再是空壳——第一个真正的工具模块 `doc_reader` 上线。赵岩那边的 OCR 文本等着进知识库，读文件这一步不能写死在 day03 的菜单里。


**陈默**：打开 `file_demos.py`。三行 `write_text`、`read_text`、`stat.st_size`——下午 `DocumentRecord.size_bytes` 就从这儿来。

## 编码讨论（10:30）

**学员 A**：GBK 文件 `read_text(encoding='utf-8')` 炸了怎么办？

**陈默**：这就是下午 `read_text_file` 要解决的。先 `read_bytes`，再按 tuple 依次 `decode`。顺序是 utf-8、gbk、gb2312、latin-1。注意 latin-1 是「最后的退路」——它永远不会抛解码错误，但可能是乱码。

**学员 B**：为啥不用 chardet？

**陈默**：MVP 不加依赖，行为可测。12 个 pytest 里有一条专门测 GBK fallback。企业里**可预测**有时比**智能**更重要。

## 下午 API 走查（14:00）

**陈默**：`DocumentRecord` 是 dataclass，不是 BaseModel。它就是流水线运单，不需要 `from_dict`。

（投影 `doc_reader.py`）

```python
record = DocumentRecord(path=..., content=..., encoding=..., size_bytes=...)
```

**陈默**：`clean=True` 时多两个字段：`cleaned` 和 `stats`。`stats` 是 dict，来自 `utils.text_utils.clean_text`。tools 调 utils，符合 PACKAGE_STRUCTURE 箭头方向。

**林晓**：`mask_phone` 为什么在 clean 之后？

**陈默**：清洗会删空格、改标点。先把文本规范化，再跑正则 `1\d{10}`，命中率高一些。计数写进 `stats['phone_masked']`，demo 脚本会打印。
