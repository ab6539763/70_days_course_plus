# Day 18 企业案例集：意图路由

**场景**：智链科技及虚构客户 — 意图分类落地故事

---

## 案例 1：理财客服热线文本分流

**背景**：日均 3 万条 IM，人工坐席成本高。

**方案**：

- 第一层 `RuleBasedIntentClassifier` 分四类 + general  
- `product_faq` → 自动回复 + 免责声明  
- `compliance_review` → 升级合规专员队列  
- `general` 低置信 → 澄清话术  

**效果**：首句自动模板命中率 68%（规则版），人工切换模板次数下降 90%。

**林晓角色**：编写 `DEFAULT_KEYWORD_RULES` 初版，每周根据未命中日志增补关键词。

---

## 案例 2：合规部宣传文案预审

**背景**：市场部提交 200+ 宣传语/周。

**痛点**：有人用 `/template compliance_review`，有人忘记切换，审阅标准不一致。

**方案**：

```python
assistant = ChatAssistant(
    client=client,
    intent_router=IntentRouter(),
    auto_route=True,
)
```

关键词「审阅」「宣传语」「合规」强制高优先级 `INTENT_PRIORITY`。

**关键决策**：`test_priority_compliance_over_rag` 来自真实纠纷句「根据文档审阅宣传语」。

## 案例 3：内部知识库问答（RAG 前奏）

**背景**：Day 17 `RAG_QA` 需要 `{context}`，运营不会手动贴文档。

**方案**：

```python
router = IntentRouter(context_provider=load_from_doc_reader)
```

仅当 `rag_qa` 意图时注入 context；避免摘要场景塞入无关长文。

**演进**：Day 28 向量检索替换 `read_document` 截断。

---

## 案例 4：多业务线模板隔离

**背景**：子公司 A 理财、子公司 B 保险，共用 NexusAgent 代码库。

**方案**：

```python
router_a = IntentRouter(
    classifier=RuleBasedIntentClassifier(rules=RULES_A),
    company="智链理财",
)
router_b = IntentRouter(
    classifier=RuleBasedIntentClassifier(rules=RULES_B),
    company="智链保险",
)
```

意图名可复用，关键词与 `company` 变量分化。

## 案例 5：灰度发布与 A/B

**背景**：新产品 FAQ 模板 `product_faq_v2` 试运行。

**方案**：

- 10% 流量 `INTENT_TEMPLATE_MAP` 映射到 v2  
- `/route` 供运营验收再全量  
- 指标：用户满意度、合规投诉率  

周航在 CI 加回归：`pytest tests/day18` + 金标准 jsonl。

---

## 案例 6：失败复盘 — 「总结」误路由 FAQ

**事件**：用户「总结一下理财产品的风险」→ `product_faq`（理财、产品、风险）与 `doc_summary`（总结）同分。

**根因**：`product_faq` 在 priority 中高于 `doc_summary` 仅当同分——本句 doc 2 词、faq 3 词，faq 胜出。

**修复**：产品明确「含总结动词优先摘要」→ 调整 priority 或给 summary 动词加权。

**教训**：规则引擎需要**业务复盘闭环**，非一劳永逸。
