# ZL-NA-REQ-015 需求文档

**需求编号**：ZL-NA-REQ-015  
**需求名称**：Token 计数与成本估算  
**优先级**：P0  
**Sprint**：Sprint 3 首日  
**状态**：已交付

---

## 1. 背景

智链科技 NexusAgent 内测用户在 Day 14 多轮 CLI 助手上线后，出现 API 费用异常增长。根因分析表明：每轮 `complete(messages)` 发送**完整历史**，`prompt_tokens` 随轮次累积。产品要求在助手内提供 **Token 可视化** 与 **费用估算**，建立成本意识，为后续上下文裁剪与 RAG 优化铺垫。

## 2. 目标用户

- 内测理财顾问（关心「聊久了要花多少钱」）
- 开发与测试（CI 验证计量逻辑）
- 运维与财务（会话级用量报表）

## 3. 功能需求

### FR-001 本地 Token 估算

| 项 | 描述 |
|----|------|
| 输入 | 纯文本字符串或 `ChatMessage` 列表 |
| 规则 | CJK 字符约 1 token/字；其他字符约 4 字符 1 token |
| 消息开销 | 每条 message 额外 +4 tokens（role、分隔符近似） |
| 输出 | 非负整数估算值 |
| 约束 | 空文本返回 0；不依赖第三方分词库 |

### FR-002 API Usage 解析

| 项 | 描述 |
|----|------|
| 输入 | `ChatCompletionResult` 或 `usage` 字典 |
| 输出 | `TokenUsage(prompt_tokens, completion_tokens, total_tokens)` |
| 约束 | 与 Day 5 `parse_chat_completion` 字段一致 |

### FR-003 费用估算

| 项 | 描述 |
|----|------|
| 默认单价 | 输入 ¥1.0/百万 token；输出 ¥2.0/百万 token |
| 计算 | `prompt_tokens/1e6 * input_price` + `completion_tokens/1e6 * output_price` |
| 输出 | `TokenCost` 含 `format_yuan()` 格式化 |

### FR-004 估算与 API 对比

- `compare_estimate(usage)` 输出本地 prompt 估算与 API `prompt_tokens` 的偏差百分比
- 用于教学：理解启发式与真实 BPE 的差异

### FR-005 会话级累计

| 项 | 描述 |
|----|------|
| 对象 | `TokenSessionTracker` |
| 行为 | 每轮 `record_turn(result, messages_before_reply)` 累加 |
| 输出 | `summary()` 一行摘要；`report()` 含最近一轮与偏差 |

### FR-006 CLI 集成

| 命令 | 行为 |
|------|------|
| `/tokens` | 输出 `TokenSessionTracker.report()` |
| 开关 | `ChatAssistant(track_tokens=False)` 时提示「未启用」 |

### FR-007 chat_turn 挂接

- 在 `complete` **之前** 快照 `messages_snapshot = list(self.history.messages)`
- `complete` 成功后调用 `token_tracker.record_turn(result, messages_snapshot)`

| 编号 | 要求 |

## 5. 验收标准

```bash
export PYTHONPATH=src NEXUS_LLM_MOCK=1
python3 src/day15/token_counter_demo.py
python3 src/day15/assistant_token_demo.py
python3 -m pytest tests/day15/ -v
```

- `estimate_tokens("") == 0`
- 中文样本文本估算 ≥ 4（「你好世界」）
- 英文样本文本估算 ≥ 2（「hello world」）
- `TokenSessionTracker` 两轮后 `turns == 2`
- `/tokens` 输出含累计 token 或费用信息
