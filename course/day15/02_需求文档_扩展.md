## 1. 扩展背景

MVP 的 `token_counter.py` 满足教学与内测可视化。智链科技 Phase 2 后续迭代需预埋以下能力接口，今日以文档与常量形式约定，代码可选实现。

## 2. 扩展功能需求

### EFR-001 模型差异化单价

| 模型 | 输入 ¥/M | 输出 ¥/M | 备注 |
|------|----------|----------|------|
| deepseek-chat | 1.0 | 2.0 | 教学默认 |
| gpt-4o-mini | 按官网 | 按官网 | 未来多模型路由 |
| 私有化部署 | 0 | 0 | 仅计 GPU 算力 |

`TokenCounter(input_price_per_m=..., output_price_per_m=...)` 已支持构造注入。

### EFR-002 预算告警阈值

| 级别 | 会话累计费用 | 行为 |
|------|-------------|------|
| INFO | < ¥0.01 | 正常 |
| WARN | ¥0.01 – ¥0.10 | `/tokens` 附加 ⚠️ |
| CRITICAL | > ¥0.10 | 建议 `/clear` 或结束会话 |

MVP 不实现自动拦截，仅文档约定。

### EFR-003 组织级报表字段

未来 BI 对接需导出：

```json
{
  "session_id": "uuid",
  "user_id": "advisor-042",
  "turns": 8,
  "prompt_tokens": 4200,
  "completion_tokens": 890,
  "total_cost_yuan": 0.00598,
  "model": "deepseek-chat"
}
```

### EFR-004 估算精度 SLA

| 场景 | 可接受偏差 |
|------|-----------|
| 纯中文短句 | ±15% |
| 纯英文 | ±25% |
| 中英混合 + 数字 | ±20% |
| 含大量标点/代码 | ±40%（建议升级 tiktoken） |

`compare_estimate` 输出用于监控偏差分布。

## 3. 用户故事扩展

### US-015-A 理财顾问小王

> 作为内测顾问，我希望每轮对话后看见本轮 token，以便控制追问深度。

**验收**：`chat_turn` 返回或附加 `usage_summary()`（可选增强，MVP 用 `/tokens`）。

### US-015-B 运维小李

> 作为运维，我希望 Mock CI 用固定 usage 样本，以便回归测试不漂移。

**验收**：`assistant_token_demo.py` 中 `SAMPLE["usage"]` 固定值。

### US-015-C 架构师陈默

> 作为架构师，我希望计量层与对话层解耦，以便替换为 tiktoken 而不改 ChatAssistant。

**验收**：`TokenSessionTracker` 仅依赖 `TokenCounter` 接口。

## 4. 多轮上下文膨胀 — 量化需求

产品需提供「教育型」示意图数据：

| 轮次 | 假设每轮新增 user+assistant 各 50 字 | 累计 prompt 趋势 |
|------|--------------------------------------|------------------|
| 1 | system+user | ~150 |
| 3 | +2 轮历史 | ~450 |
| 10 | +9 轮历史 | ~1,500+ |

课件与 demo 需能复现「越长越贵」直觉。

## 5. 安全与合规

- Token 报表不得包含用户 PII 明文（仅统计数字）
- 费用为**估算**，财务对账以云厂商账单为准
- 日志中 usage 字段可留存，消息正文按既有脱敏策略

## 7. 与 Day 16 流式的接口约定

流式响应可能在最后一个 SSE chunk 携带 `usage`。扩展需求：

- `TokenUsage.from_usage_dict` 保持兼容
- 流式完成前 `prompt_tokens` 可能为 0，UI 应显示「统计中…」
- 今日非流式路径：`complete` 一次返回完整 `usage`
