# ZL-NA-REQ-041 产品需求文档（PRD）

**需求名称**：StateGraph 状态图编排
**优先级**：P0
**平台版本**：v0.41.0

---

## 1. 背景

产品要求「先规划、再执行工具、最后单独一步生成答案」三个阶段要能分别插桩、分别测试，AgentExecutor 的单一 while 循环耦合太紧。 引入轻量 StateGraph：add_node 注册 planner/tool_runner/answer 三个节点，add_conditional_edges 控制何时回到 planner、何时进入 answer，node_path 记录实际走过的节点序列。

## 2. 目标

- `agent/state_graph.py` — StateGraph — add_node/add_edge/compile/invoke
- `agent/graph_state.py` — AgentGraphState 节点间共享状态
- `agent/rag_agent_graph.py` — RAGAgentGraph 三节点预置图
- `agent/graph_config.py` — GraphConfig — max_iterations
- `GET/PUT /api/agent/graph-config` 配置读写
- `POST /api/agent/graph-preview` 无状态预览

- `POST /api/chat` + `graph_mode=true` → `graph_trace`

## 3. 功能需求

### FR-001 StateGraph — add_node/add_edge/compile/invoke

- 实现位置：`agent/state_graph.py`

### FR-002 AgentGraphState 节点间共享状态

- 实现位置：`agent/graph_state.py`

### FR-003 RAGAgentGraph 三节点预置图

- 实现位置：`agent/rag_agent_graph.py`

### FR-004 GraphConfig — max_iterations

- 实现位置：`agent/graph_config.py`

### FR-005 持久化与 status

- `store.json` 新增对应 config 字段
- `GET /api/knowledge/status` 含该 config 字段
- `platform_version` 为 `v0.41.0`

### FR-006 Chat 集成

- `api/chat.py` 在 `graph_mode=true` 且配置 `enabled` 时走本日管线
- `ChatResponse` 新增 `graph_trace` 字段（及 node_path, tools_used）

### FR-007 演示与测试

- `day41/graph_demo.py` 打印决策/委派轨迹
- `day41/graph_api_demo.py` 演示 REST API
- `tests/day41/` 17 项覆盖单元 + API + chat

## 4. 非功能需求

### NFR-001 可观测性

每次调用都返回结构化 `graph_trace`，可用于审计与教学演示。

### NFR-002 兼容性

`graph_mode=false`（默认）时行为与之前完全一致，不影响既有回归。

### NFR-003 可测试性

核心类可脱离 FastAPI 直接单测（构造 `ToolExecutor` 后 `invoke`/`run`）。

## 5. 非目标

- 接入真实大模型 function-calling（当前仍为规则/mock 决策）
- 跨 session 的长期记忆持久化
