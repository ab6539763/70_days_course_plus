## 第一节：为何需要函数（9:00 - 9:20）

**DRY 原则**：Don't Repeat Yourself — 每一处知识在系统中都应有单一、明确、权威的表示。

在 Day 1-5 的代码里，你已经多次写下类似片段：

```python
if not title.strip():
    print("标题不能为空")
    return

if not path.exists():
    return default

with open(path, encoding="utf-8") as f:
    data = json.load(f)
```

这些不是「业务逻辑」，而是**横切关注点**（cross-cutting concerns）：校验、IO、格式化。把它们复制到十个文件里，将来改一处就要改十处，必然漏改、出 bug。

**函数**把一段逻辑命名、封装，通过参数输入、返回值输出，实现复用：

```python
# 重复 3 次 — 维护噩梦
print("=" * 40)
print("  标题")
print("=" * 40)
```

```python
def print_banner(title: str) -> None:
    print("=" * 40)
    print(f"  {title}")
    print("=" * 40)

print_banner("待办管理器")
print_banner("文本清洗")
```

陈默在站会上说：**「函数是工程化的最小单元。类（Day 8）是函数的集合；模块是函数的仓库；包是模块的仓库。」**

## 第二节：函数定义与调用（9:20 - 10:00）

### 2.1 语法结构

```python
def 函数名(参数1, 参数2):
    """文档字符串 docstring — 说明用途、参数、返回值"""
    语句块
    return 返回值  # 可选
```

示例：

```python
def add(a: int, b: int) -> int:
    """两数之和"""
    return a + b

result = add(3, 5)  # 8
```

**调用栈**：`add(3, 5)` 时 Python 创建新的栈帧，局部变量 `a=3, b=5`，执行 `return 8` 后栈帧销毁，结果赋给 `result`。

### 2.2 无返回值

```python
def greet(name: str) -> None:
    print(f"Hello, {name}")
    # 没有 return 时，隐式 return None

greet("NexusAgent")
```

区分 **打印** 与 **返回**：`print` 给人看；`return` 给程序用。企业代码里，UI 层可以 print，业务层应 return 数据。

### 2.3 函数是一等公民

```python
def double(x):
    return x * 2

f = double      # 函数可以赋给变量
print(f(10))    # 20
```

后续 Day 15 会把函数当作参数传给 `map`、`sorted`，Day 39 的 Agent 工具注册也是「函数即工具」。

## 第三节：参数类型（10:00 - 11:00）

### 3.1 位置参数与关键字参数

```python
def create_todo(title: str, description: str, priority: int = 2) -> dict:
    return {"title": title, "description": description, "priority": priority}

create_todo("任务A", "描述")                    # 位置参数
create_todo("任务B", priority=1, description="")  # 关键字参数，顺序可打乱
```

**规则**：位置参数在前，带默认值的参数在后；调用时关键字参数必须在位置参数之后。

### 3.2 默认参数

```python
def connect(host: str, port: int = 5432, timeout: int = 30) -> None:
    ...

connect("localhost")
connect("localhost", 3306)
connect("localhost", timeout=60)
```

**经典陷阱**：默认参数在**函数定义时**只求值一次，不要用可变对象作默认值！

```python
# 错误！第二次调用 append_item(2) 会复用同一个 list
def append_item(item, lst=[]):
    lst.append(item)
    return lst

# 正确
def append_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst
```

`utils/json_utils.load_json(path, default=None)` 里的 `default=None` 就是正确写法。

### 3.3 *args — 可变位置参数

```python
def log(message: str, *args) -> None:
    print(message)
    for a in args:
        print("  -", a)

log("今日任务", "清洗", "CLI", "JSON")
```

函数体内 `args` 是 **tuple**。适合参数个数不定的场景，例如未来的日志聚合。

### 3.4 **kwargs — 可变关键字参数

```python
def build_config(model: str, temperature: float = 0.7, **extra) -> dict:
    config = {"model": model, "temperature": temperature}
    config.update(extra)
    return config

cfg = build_config("deepseek-chat", max_tokens=1024, stream=False)
```

`extra` 是 **dict**。灵犀平台调用 LLM API 时，不同模型支持不同字段，用 `**kwargs` 转发最灵活。

### 3.5 仅关键字参数（Python 3）

```python
def save_json(path, data, *, indent: int = 2) -> None:
    ...
```

`*` 之后的参数必须用关键字传递：`save_json(p, d, indent=4)`，避免把 `2` 误传给错误位置。

## 第四节：返回值（11:00 - 11:40）

### 4.1 单返回值

```python
def count_done(todos: list) -> int:
    return sum(1 for t in todos if t.get("done"))
```

### 4.2 多返回值（实际是 tuple 解包）

```python
def get_stats(todos: list) -> tuple[int, int]:
    total = len(todos)
    done = sum(1 for t in todos if t.get("done"))
    return total, done

total, done = get_stats(store["todos"])
```

`text_utils.clean_text` 返回 `(str, dict)` 统计信息，是同一模式。

### 4.3 提前 return

```python
def find_todo(todos: list, todo_id: int) -> dict | None:
    for t in todos:
        if t.get("id") == todo_id:
            return t
    return None  # 未找到
```

**卫语句**（guard clause）：先处理异常情况并 return，主逻辑保持扁平，可读性更好。

### 4.4 validators 的「错误消息」模式

```python
def require_non_empty(value: str, field_name: str = "字段") -> str | None:
    if value is None or not str(value).strip():
        return f"{field_name}不能为空"
    return None
```

返回 `None` 表示通过，返回 `str` 表示错误消息。调用方：

```python
err = require_non_empty(title, "标题")
if err:
    print(f"  ⚠️  {err}")
    return
```

比 `raise` 更适合 CLI 交互；API 层（Day 22+）会改成抛 HTTPException。

## 第五节：类型注解（11:40 - 12:00）

```python
def clean_text(raw: str, *, to_lower: bool = False) -> tuple[str, dict]:
    ...
```

| 注解 | 含义 |
|------|------|
| `str` | 字符串 |
| `int \| None` | 整数或 None |
| `list[dict]` | 字典列表 |
| `-> None` | 无有意义返回值 |
| `* , to_lower` | 仅关键字参数 |

类型注解**不强制运行时检查**（除非用 pydantic），但 IDE 会提示错误，Day 23 FastAPI 会用来做请求体验证。

## 第六节：docstring 规范

```python
def load_json(path: Path, default: Any = None) -> Any:
    """
    安全加载 JSON 文件

    Args:
        path: 文件路径
        default: 文件不存在或解析失败时的返回值

    Returns:
        解析后的 Python 对象，或 default
    """
```

团队规范（见 `team/GIT_CONVENTION.md`）：公共函数必须有 docstring；私有函数 `_helper` 可简短说明。

## 上午小结

| 概念 | 要点 |
|------|------|
| def | 定义可复用代码块 |
| return | 返回结果；无 return → None |
| 默认参数 | 用 None 代替可变默认值 |
| *args | 可变位置参数 → tuple |
| **kwargs | 可变关键字参数 → dict |
| 类型注解 | 提升可读性与 IDE 支持 |
| docstring | 三引号，说明 Args/Returns |
