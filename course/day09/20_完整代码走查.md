## 一、llm_base.py 走查

```python
from abc import ABC, abstractmethod
from typing import TypeVar

T = TypeVar("T", bound="BaseModel")
```

`TypeVar` 绑定 BaseModel，使 `from_dict_safe` 返回类型为具体子类而非笼统 BaseModel。

```python
class ModelValidationError(ValueError):
    def __init__(self, message: str, *, model_type: str = "BaseModel") -> None:
        self.model_type = model_type
        super().__init__(f"[{model_type}] {message}")
```

**设计点**：继承 ValueError 而非 Exception，便于分层捕获；保留 `model_type` 字段供日志系统索引。

```python
class BaseModel(ABC):
    @abstractmethod
    def validate(self) -> str | None: ...
```

三个抽象方法构成**最小契约**。任何新模型必须思考：我如何校验？如何导出？如何从 JSON 还原？

```python
def ensure_valid(self) -> None:
    err = self.validate()
    if err:
        raise ModelValidationError(err, model_type=self.model_type)
```

从「返回错误消息」演进到「抛异常」，标志项目从 CLI 玩具向服务化过渡。

## 六、polymorphism_demo.py 走查

`ModelRegistry` 是 Day 39 **工具注册表** 的微型版：

```python
def register(self, model: BaseModel) -> str | None:
    err = model.validate()
    if err:
        return err
    self._items.append(model)
    return None
```

`serialize_models` 展示**批量多态序列化**：

```python
def serialize_models(models: list[BaseModel]) -> list[dict]:
    return [m.to_json_ready() for m in models]
```

任何子类列表传入即可，无需 if isinstance 分支。

## 九、常见走查问题 FAQ

**Q：为何不用 dataclass + Protocol？**  
A：培训需显式经历 ABC；Protocol 适合结构子类型，后续选修。

**Q：BaseModel 要加 __init__ 吗？**  
A：不必。各子类字段差异大，统一 __init__ 反而别扭。

**Q：Contact 的 __eq__ 与 ChatMessage 的 __eq__ 不一致？**  
A：Contact 比 to_dict；ChatMessage 比含 created_at。领域决策不同，作业讨论统一策略。
