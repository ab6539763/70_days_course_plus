# ZL-NA-REQ-038 产品需求文档（PRD）

**需求名称**：多轮 Self-RAG 校验重试
**优先级**：P0
**平台版本**：v0.38.0

---

## 1. 背景

Day37 校验拒答后用户体验很差——机器人直接说「无法确认」，一次机会就放弃了，没有给系统补救的余地。 实现 apply_validation_retry：校验失败且 retry_on_fail 时，用 rag_wide 意图强制放大检索池重新召回，再校验一次；仍失败才真正拒答。

## 2. 目标

- `rag/validation_retry.py` — apply_validation_retry — 校验失败后 rag_wide 重检索再校验
- `GET/PUT /api/knowledge/validation-config` 配置读写
- `POST /api/knowledge/validation-retry-preview` 无状态预览
- `POST /api/chat` 端到端集成

## 3. 功能需求

### FR-001 apply_validation_retry — 校验失败后 rag_wide 重检索再校验

- 实现位置：`rag/validation_retry.py`

### FR-002 持久化与 status

- `store.json` 新增 `validation_config` 字段
- `GET /api/knowledge/status` 含 `validation_config`
- `platform_version` 为 `v0.38.0`

### FR-003 Chat 集成

- `api/chat.py` 在管线中调用本日模块
- `ChatResponse` 相应字段附带本日审计信息

### FR-004 演示与测试

- `day38/retry_demo.py` 打印对比结果
- `day38/retry_api_demo.py` 演示 REST API
- `tests/day38/` 15 项覆盖单元 + API + chat

## 4. 非功能需求

### NFR-001 可观测性

status / preview 接口可读当前 `validation_config`。

### NFR-002 兼容性

`ValidationConfig.enabled=false` 时行为回退到 Day 37 逻辑，不影响既有回归。

### NFR-003 可测试性

`apply_validation_retry` 可脱离 FastAPI 直接单测。

## 5. 非目标

- 接入真实模型替换当前 mock 规则实现
- 跨会话的长期缓存
