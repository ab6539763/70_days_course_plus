## 2. 易混淆概念讲法

### FAQ 直答 vs faq_lookup vs /similar

用同一问题「投资有风险吗」三次演示：

1. `/similar` → 预览格式，不调 LLM  
2. `/tool faq_lookup 投资有风险吗` → `[faq_lookup]` 前缀  
3. `orchestrator.handle_message` → `[FAQ 直答·xx%]` 前缀，可能不调 LLM  

### 编排器 vs 执行器

- **编排器**：决定走哪条**业务路径**（FAQ 还是 LLM）  
- **执行器**：给定工具名，**执行函数**  

类比：编排器是餐厅领位，执行器是后厨做单道菜。

## 附录：智链科技 NexusAgent 工具命名规范（节选）

工具名用小写蛇形；动词在前：lookup/search/classify/estimate；避免缩写；description 用中文完整句；parameters 必填尽量少；handler 禁止副作用（写库、发邮件）除非另开需求。Day 21 四工具是规范范例。扩展工具须过架构评审。

## 附录：与 Day 22–24 的接口约定（冻结）

`handle_message(user_text: str) -> str` 在 Sprint 3 内冻结。返回文本可含前缀标签，前端字符串匹配即可。Day 23 可增 JSON 端点，但不改此方法签名。Breaking change 须升 Sprint 版本号并更新全部课件。

## 附录：常见问题深度解答二十则（节选）

**Q1**：为何不用 LangChain Tools Day 21 就上？  
A：先理解原生注册表，Day 25 再对比框架，学习曲线更稳。

A：Day 21 未禁止，但编排应在 orchestrator 显式写，避免 handler 内隐式链式调用。  

**Q3**：FAQ 库谁维护？  
A：运营赵岩团队，开发提供 matcher 接口。  

**Q4**：CI 为何跑 scripted 周测？  
A：验证题目与评分逻辑未损坏。  

**Q5**：能否用真实 API 跑 demo？  
A：课堂统一 NEXUS_LLM_MOCK=1，课外自选。
