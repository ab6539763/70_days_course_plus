## 1. 为什么必须学 Git？

在企业开发中，Git 不是可选项。

- 你的代码需要被 Code Review
- 你需要和同事并行开发不同功能
- 上线出 bug 需要回滚到上一个版本
- 培训结束时，你的 GitHub 主页需要展示 70 天的提交记录

陈默总监说过：「**没有 Git 提交记录的简历，在 AI 岗位上行不通。**」

## 2. Git 核心概念（5 分钟理解）

```
工作区（你编辑的文件）
    │ git add
    ▼
暂存区（staging area，准备提交的快照）
    │ git commit
    ▼
本地仓库（你的 commit 历史）
    │ git push
    ▼
远程仓库（GitHub 上的团队共享仓库）
```

**三个日常命令**：

```bash
git add .                    # 把所有修改放入暂存区
git commit -m "描述信息"      # 提交到本地仓库
git push                     # 推送到远程仓库
```

## 3. 首次 Git 配置

```bash
# 设置用户名和邮箱（全局，只需一次）
git config --global user.name "你的名字"
git config --global user.email "your.email@example.com"

# 验证
git config --list
```

## 4. Day 1 提交流程（实操）

### 4.1 克隆仓库（如果还没克隆）

```bash
git clone https://github.com/ab6539763/70_days_course_plus.git
cd 70_days_course_plus
```

### 4.2 创建功能分支

```bash
git checkout -b feature/day01-personal-info-card
```

**为什么不用 main？**

main 是保护分支，不允许直接 push。所有开发在 feature 分支进行，完成后提 PR 合并。详见 `team/GIT_CONVENTION.md`。

### 4.3 编写代码

在 `nexus-agent-platform/src/day01/` 下完成你的 `personal_info_card.py`。

### 4.4 查看修改

```bash
git status
# 会显示哪些文件被修改/新增

git diff
# 显示具体修改内容
```

### 4.5 提交

```bash
git add nexus-agent-platform/src/day01/
git commit -m "feat(day01): 实现开发者入职信息采集 CLI

- 采集姓名、年龄、职位、邮箱
- 生成 ZL-YYYYMMDD-001 格式工号
- 输出 ASCII 格式化信息卡片
- 提取常量到 constants.py

Refs: ZL-NA-REQ-001"
```

### 4.6 推送

```bash
git push -u origin feature/day01-personal-info-card
```

### 4.7 创建 Pull Request

1. 打开 GitHub 仓库页面
2. 点击 "Compare & pull request"
3. 标题：`[Day01] 开发者入职信息采集 CLI`
4. 描述：关联 ZL-NA-REQ-001，附运行截图
5. 指定 Reviewer：赵岩
6. 提交 PR

## 5. 常见问题

### Q: push 时要求输入用户名密码？

GitHub 已不支持密码认证。请使用 Personal Access Token (PAT)：

1. GitHub → Settings → Developer settings → Personal access tokens
2. Generate new token，勾选 `repo` 权限
3. push 时密码处粘贴 token

### Q: 提交了错误的文件怎么办？

```bash
# 撤销最近一次 commit（保留文件修改）
git reset --soft HEAD~1
```

### Q: .venv 目录要不要提交？

**不要！** `.gitignore` 已配置忽略。虚拟环境目录很大且因人而异。
