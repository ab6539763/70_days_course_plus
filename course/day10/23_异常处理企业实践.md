## 第一章：异常是什么

异常是**控制流**机制：错误发生时，Python 沿调用栈向上查找 `except`，若无人处理则程序终止并打印 traceback。

```python
def a():
    b()
def b():
    c()
def c():
    raise ValueError("deep error")
```

traceback 显示 c → b → a 调用链，便于定位。

## 第二章：try 语句完整形式

```python
try:
    suite
except ExceptionType as e:
    handler
else:
    no_exception_suite
finally:
    cleanup_suite
```

- `else`：仅 try 无异常时执行  
- `finally`：无论是否异常都执行（关闭文件、释放锁）

## 第三章：NexusError 设计走读

```python
class NexusError(Exception):
    def __init__(self, message: str, *, code: str = "NEXUS_ERROR"):
        self.message = message
        self.code = code
        super().__init__(message)
```

**为何不用纯字符串异常？**  
`code` 便于监控告警分类；`message` 给人看。

## 第四章：raise 的三种形式

```python
raise ModelValidationError("bad", model_type="X")  # 新建
raise  # 当前 except 块内重新抛出
raise NewError("wrap") from original_exc  # 链
```

**异常链**在 Day 12 调试 API 错误时至关重要：底层 `requests` 异常包装为 `StorageError`。

## 第五章：服务层异常转换

```python
def save(self, path: Path) -> None:
    try:
        save_json(path, data)
    except OSError as exc:
        raise StorageError(f"写入失败: {exc}", path=str(path)) from exc
```

**模式**：底层标准异常 → 领域 NexusError，上层只处理 NexusError。

## 第七章：pytest 测异常

def test_bad_path():
    with pytest.raises(ConfigError):
        get_path("nonexistent")
