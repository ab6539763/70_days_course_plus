## 第五节：异常基础（14:00 - 14:45）

异常是程序运行时错误的传播机制。未捕获的异常会导致进程退出并打印 **traceback**（调用栈）。

```python
try:
    risky()
except ValueError as e:
    print(f"值错误: {e}")
except NexusError as e:
    print(f"业务错误 [{e.code}]: {e.message}")
except Exception as e:
    print(f"未预期: {e}")
    raise  # 可选：重新抛出
else:
    print("无异常时执行")
finally:
    print("始终执行，常用于清理资源")
```

### 5.1 traceback 阅读法

从下往上读：最后一行是**直接原因**，往上是调用者。企业调试第一技能。

### 5.2 捕获顺序

子类在前，父类在后：

```python
except ModelValidationError:  # 先
    ...
except NexusError:            # 后
    ...
```

若顺序反了，子类分支永远进不去。

**原则**：

1. 捕获**具体**异常，避免 bare `except:`
2. 不知道如何处理时 `raise` 向上抛
3. 使用 `raise NewError(...) from exc` 保留链

## 第六节：NexusError 体系（14:45 - 15:30）

```python
from core.exceptions import NexusError, ModelValidationError

try:
    ChatMessage("bot", "x").ensure_valid()
except ModelValidationError as e:
    print(e.code)        # MODEL_VALIDATION
    print(e.model_type)  # ChatMessage
```

`ModelValidationError` 多重继承 `ModelError` + `ValueError`：

- `except NexusError` — 业务层统一捕获
- `except ValueError` — Day 9 代码兼容
