# ZL-NA-REQ-036 产品需求文档（PRD）

**需求名称**：自适应路由（Query Router）
**优先级**：P0
**平台版本**：v0.36.0

---

## 1. 背景

Day35 全量扩展后，简单的「客服电话多少」这类 FAQ 问句也要走多路召回 + 改写，延迟不必要地增加。 引入 RuleBasedQueryRouter：按意图分三档路由——faq_fast 跳过 expand/rewrite 直接查，rag_standard 走常规管线，rag_wide 对模糊/合规问句开启全部增强手段。

## 2. 目标

- `rag/query_router.py` — RuleBasedQueryRouter — faq_fast / rag_standard / rag_wide
- `rag/routing_retriever.py` — RoutingRetriever — 动态 expand/rewrite 开关
- `rag/route_config.py` — RouteConfig — enabled / fallback_intent
- `GET/PUT /api/knowledge/route-config` 配置读写
- `POST /api/knowledge/route-preview` 无状态预览
- `POST /api/chat` 端到端集成

## 3. 功能需求

### FR-001 RuleBasedQueryRouter — faq_fast / rag_standard / rag_wide

- 实现位置：`rag/query_router.py`

### FR-002 RoutingRetriever — 动态 expand/rewrite 开关

- 实现位置：`rag/routing_retriever.py`

### FR-003 RouteConfig — enabled / fallback_intent

- 实现位置：`rag/route_config.py`

### FR-004 持久化与 status

- `store.json` 新增 `route_config` 字段
- `GET /api/knowledge/status` 含 `route_config`
- `platform_version` 为 `v0.36.0`

### FR-005 Chat 集成

- `api/chat.py` 在管线中调用本日模块
- `ChatResponse` 相应字段附带本日审计信息

### FR-006 演示与测试

- `day36/route_demo.py` 打印对比结果
- `day36/route_api_demo.py` 演示 REST API
- `tests/day36/` 20 项覆盖单元 + API + chat

## 4. 非功能需求

### NFR-001 可观测性

status / preview 接口可读当前 `route_config`。

### NFR-002 兼容性

`RouteConfig.enabled=false` 时行为回退到 Day 35 逻辑，不影响既有回归。

### NFR-003 可测试性

`RoutingRetriever` 可脱离 FastAPI 直接单测。

## 5. 非目标

- 接入真实模型替换当前 mock 规则实现
- 跨会话的长期缓存
